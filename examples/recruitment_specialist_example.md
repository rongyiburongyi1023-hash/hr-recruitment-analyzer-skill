# 案例一：招聘专员岗位分析

> 本案例为教学用虚构场景，指标需由实际组织确认。

## 输入

```yaml
task_type: job_analysis
job_title: 招聘专员
business_context: 约300人的连锁零售企业，业务扩张；归属人力资源部，向招聘经理汇报
job_objective: 支持门店和总部岗位招聘，改善到岗速度与候选人体验
responsibilities:
  - 发布职位、筛选简历、安排面试
  - 对接用人部门
  - 维护招聘渠道
  - 统计招聘数据
performance_expectations: 每月同时负责约15个岗位；具体时效和质量目标未提供
constraints: 需要偶尔到门店沟通需求
```

## Skill 处理

1. 将“支持招聘”拆为需求澄清、人才获取、流程推进和数据改进四个结果领域。
2. 将事务动作映射到关键产出，避免只罗列“发布、筛选、安排”。
3. 从关键工作场景反推需求访谈、渠道运营、候选人沟通、流程管理和数据意识。
4. 未提供的时效、成本和质量 KPI 不作虚构，列为待确认项。

## 输出结果

### 岗位目标

在既定招聘计划和用人标准下，完成门店及总部岗位的招聘流程交付，通过有效的需求沟通、渠道管理和过程跟进，提高招聘效率与候选人体验。

### 关键产出

| 关键产出 | 成功表现 | 建议指标/证据 |
| --- | --- | --- |
| 招聘需求得到准确转化 | JD 与筛选标准经用人部门确认，减少反复变更 | 需求确认记录、JD 返工情况 |
| 招聘流程按计划推进 | 关键节点可追踪，候选人和面试官获得及时反馈 | 招聘周期、节点及时率 |
| 有效候选人稳定供给 | 渠道与岗位匹配，推荐人选符合基本标准 | 有效简历率、面试通过率 |
| 招聘数据支持改进 | 数据准确，能识别渠道或流程瓶颈 | 报表准确性、改进建议 |

### 核心职责

| 职责领域 | 主要职责 | 对应产出 |
| --- | --- | --- |
| 需求管理 | 与用人经理澄清岗位目标、优先级和评价标准，维护招聘计划 | 需求得到准确转化 |
| 人才获取 | 选择渠道、发布 JD、主动寻访并完成初步筛选 | 有效候选人供给 |
| 流程与体验 | 协调面试、跟进反馈、维护候选人沟通并支持录用衔接 | 流程按计划推进 |
| 数据改进 | 维护招聘台账，分析周期、转化率和渠道效果 | 数据支持改进 |

### 任职资格

**必备条件**

- 能进行结构化需求沟通，并把业务描述转为招聘条件。
- 具备招聘流程组织能力，能同时跟踪多个岗位及节点。
- 能进行专业、及时的候选人与用人部门沟通。
- 能使用表格或招聘系统维护准确的过程数据。

**优选条件**

- 有零售、连锁或批量招聘场景经验。
- 有招聘渠道效果分析和优化经验。

### 能力模型

| 能力 | 定义 | 关键行为 | 建议验证方式 |
| --- | --- | --- | --- |
| 需求澄清 | 准确理解并校准用人需求 | 追问业务目标；区分必备与优选；确认评价口径 | 行为面试 + 需求访谈模拟 |
| 多任务管理 | 并行推进岗位且控制节点 | 设置优先级；预警延误；维护进展记录 | 行为面试 + 情境题 |
| 关系协同 | 推动用人经理和候选人及时行动 | 明确责任与时点；处理分歧；闭环反馈 | 行为面试 |
| 数据意识 | 使用数据诊断招聘过程 | 保证数据准确；比较转化；提出改进 | 工作样本 |

### 假设与待确认项

- 建议指标仅用于讨论，尚未被组织确认。
- 需确认岗位平均招聘周期、试用期通过率等质量目标。
- 需确认门店岗位与总部岗位的工作量占比，以及出行频率。
- 需明确招聘专员在薪酬沟通和录用审批中的权限边界。
